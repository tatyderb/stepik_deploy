## TEXT Прежде чем начать: авторизация

Для использования Stepik.org API с правами существующего аккаунта на Stepik, нужна авторизация по OAuth2.

Для этого нужно перейдите по ссылке [text](https://stepik.org/oauth2/applications) и нажмите на зелёную кнопку "Создать приложение". Выберите : 
Client type - confidential,

Authorization Grant Type - client-credentials

 Если вы проходили эту процедуру, то перейдите по старому приложению, и проверьте, что эти параметры такие же. (на данном скриншоте пользователь уже создавал приложение) 

Ваши Client ID и Client Secret — это как «логин и пароль» от входа в базу данных Stepik.

Пример авторизации на Python можно найти в официальном репозитории Stepik: [oauth_auth_example.py](https://github.com/StepicOrg/Stepik-API/blob/master/examples/oauth_auth_example.py)

**Запрос:** POST https://stepik.org/oauth2/token/
**Content-Type:** application/x-www-form-urlencoded
**Authorization:** Basic base64(client_id:client_secret)

Payload:
`grant_type=client_credentials`

## TEXT Введение: Как связаны данные в Stepik

Работа с пользователями и их решениями в Stepik строится на трёх главных вещах:

**User (пользователь)**: Человек с уникальным ID и именем.

**Attempt (попытка)**: Во многих тестах варианты ответов могут перемешиваться.
Attempt сохраняет конкретный набор данных (dataset), который был показан пользователю в момент открытия задачи. Иными словами, главная функция - фиксировать условия задачи. 

**Submission (решение)**: Конкретный ответ, который пользователь отправил на проверку. Фиксирует ответ пользователя и результат проверки сервером - wrong или correct.

Для полного понимания, расмотрим ситуацию: студент, прежде чем успешно сдать задание на написание блока кода, два раза ошибся. Подразумевая, что условие задачи никак не меняется, появятся 3 решения, но в пределах 1 попытки, так как набор данных (dataset) постоянный. А если бы задача былана выбор ответа, и каждый раз варианты A, B, C перемешиваются, то было бы 3 решения и 3 попытки. 

В этом шаге мы будем получать данные о пользователе, его попытках и решениях. Чтобы это сделать, нужно выполнить соответствующие запросы, после которых нам вернётся информация в формате json. Далее код в этом формате - пример того, как выглядит ответ.


### 1.1 Получить ID студентов по классу

У вас есть список учеников в классе, class_id (ID вашего класса на Stepik).

> Запрос: GET /api/students?group={class_id}.

Вам возвращается список всех user_id, которые состоят в этой группе.
``` json
{
    "meta": {
        "page": 1,
        "has_next": false,
        "has_previous": false
    },
    "students": [
        {
            "id": 584001,
            "user": 296674444,
            "group": 11635
        },
        {
            "id": 555892,
            "user": 555888290,
            "group": 11635
        },
        {
            "id": 524003,
            "user": 123456767,
            "group": 11635
        }
    ]
}
```

**1.2 По списку ID получить ФИО всех студентов сразу**
Чтобы не искать каждого отдельно, перечислите все ID через знак &.

> Запрос: GET /api/users?ids[]=123&ids[]=456&ids[]=789

### ** 2.1 Получить основную информацию работы в классе**
Используется, чтобы увидеть общую картину: кто, что и когда сдавал.
Запрос: GET https://stepik.org/api/submissions?class=11635&page=1
Authorization: Bearer <token>

Все ответы на GET запросы разбиты на страницы. Если следующая страница существует, ее можно запросить с помощью параметра get ?page=.... По умолчанию, если параметр не указан, он равен 1.

```json
{
    "meta": {
        "page": 1,
        "has_next": true,
        "has_previous": false
    },
    "submissions": [
        {
            "id": 1515824800,
            "attempt": 1436869583,
            "user": 296745003,
            "step": 123456,
            "score": 1.0,
            "status": "correct"
        }
    ]
}
```



## TEXT Получение решений и баллов студента

**2.1 Получение балла, решения студента по шагу**
После того, как мы "познакомились" со всеми студентами, часто нужно посмотреть решение конкретного человека. Для этого нужно обратиться к submission. В отличие от простых списков, здесь нас интересует объект reply, в котором Stepik сохраняет финальный текст, отправленный учеником на проверку.

> Запрос: GET https://stepik.org/api/submissions?user={student_id}&step={step_id}
Authorization: Bearer <token>

```json
{
    "submissions": [
        {
            "id": 1515824800,
            "score": 1.0,
            "status": "correct",
            "attempt": 1436869584,
            "reply": {
                "code": "def solve():\n    print('Код студента')",
                "language": "python3"
            }
        }
    ]
}
```

**2.2 Узнать, какой вариант задания (dataset) достался студенту**
Для этого нужно сначала взять attempt_id из предыдущего запроса (пункт 2.1), а затем использовать его здесь.

>Запрос: GET https://stepik.org/api/attempts/{attempt_id}
Authorization: Bearer <token>

Пример ответа:
Самое важное здесь — поле dataset. Оно показывает именно те данные, которые были на экране у студента (например, текст задачи или порядок кнопок в тесте).

```json
{
    "attempts": [
        {
            "id": 1436869584,
            "user": 296744444,
            "dataset": {
                "options": ["А", "Б", "В"] 
            },
            "status": "active"
        }
    ]
}
```

Также с помощью попыток есть ещё один способ получить ID учащегося:
**Получить ID студента с помощью попыток решения**
> Запрос: GET /api/attempts/{attempt_id}

Authorization: Bearer <token>

```json
{
    "attempts": [
        {
            "id": 1436869584,
            "user": 296744444,
            "step": 123457
        }
    ]
}
```
